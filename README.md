## ◈ How I Think

```text
╔══════════════════════════════════════════════════════════════════╗
║                                                                  ║
║   [Observe] → [Clarify] → [Decompose] → [Design]                ║
║                                              ↓                   ║
║                         [Refine] ← [Review] ← [Implement]       ║
║                                                                  ║
╚══════════════════════════════════════════════════════════════════╝

  Observe    →  Start from real behaviour, logs, and edge cases.
  Clarify    →  Tighten the problem until success is unambiguous.
  Decompose  →  Break work into small, independently testable units.
  Design     →  Choose simple, proven tools before fancy ones.
  Implement  →  Readable. Predictable. Version-controlled.
  Review     →  Question assumptions. Validate with data, not gut.
  Refine     →  Iterate in small, safe steps. Reliability > features.
```
